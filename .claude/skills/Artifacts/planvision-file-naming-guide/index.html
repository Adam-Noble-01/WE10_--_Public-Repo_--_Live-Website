File Naming Guide — Drawing PDFs & PNGs

How to name exported drawing files so the Build tool discovers them and the PlanVision app displays them correctly. Derived from the live app parser, the manifest Build tool, and the Ashness Close reference project.

Applies to: content in 20__PlanVision__AppContent / 05__ProjectContent Reviewed: 19 Jul 2026
In one line: name every sheet XX##_T##_D##__TitleInPascalCase__IsoA2__RevX__ and export it as a matching .pdf and .png pair with that identical base name.
  • Single _ only inside the XX##_T##_D## code block. Double __ everywhere else, plus a trailing __.
  • The D## number sets the running order (files sort alphabetically), so number your sheets deliberately.
  • Both a .pdf and a .png, same base name. The PNG is what draws on screen; the PDF is the download.
  • No spaces, no -, no "Converted_From_PDF_Page" suffixes. Superseded revisions go in 00__Archive.

1Filename anatomy

Every drawing file has a base name built from a fixed set of tokens, then a .pdf or .png extension.

NP03_T02_D02__NorthElevation__IsoA2__RevC__.pdf
NP03 — Project code
2 client initials + 2-digit project number.
T02 — Phase / tab
Design phase. T01 / T02 / T03.
D02 — Document code
Sheet number. Drives sort order.
NorthElevation — Title
PascalCase, no spaces.
IsoA2 — Sheet size
Optional. Paper size metadata.
RevC — Revision
Rev + letter.
_  __ — Separators
Single inside the code block, double between segments + trailing.

The app parser reads this as: code block NP03_T02_D02  →  document code D02, then the __-separated segments become the title (North Elevation), the size is recognised and hidden from the title, and the revision shows as (Rev C). Register row: “D02 – North Elevation (Rev C)”, size column “ISO A2”.

2Token reference

TokenFormatRequired?What it means / rules
Project[A-Z][A-Z][0-9][0-9]YesClient initials (uppercase) + project number 01–99. Never 00. e.g. NP03, EB03, JH03.
Phase / TabT + 2 digitsYesT01 = Concept Design, T02 = Planning Approval, T03 = Building Regs. Must match the DesignPhase0N folder it lives in.
Document codeLetters + digitsYesD## = drawing, S## = statement (Design & Access). Zero-padded. This is the value the sort order uses, so it controls the sequence shown in the app.
TitlePascalCaseYesNo spaces. Words run together with capitals: GroundFloorPlans → “Ground Floor Plans”. & is allowed (Design&AccessStatement). Multiple __ parts join with “ – ”.
Sheet sizeIsoA2 / A2OptionalPaper size. Recognised as metadata and removed from the display title; shown separately as “ISO A2”. Include it on scaled drawings.
RevisionRev + letterRecommendedAny segment starting Rev: RevA, RevB, RevC… Shown as “(Rev A)”.
Trailing__YesEnd every base name with a double underscore before the extension.

3Separators — the part that breaks most often

Single underscore _

Used only inside the code block, to join the three codes:

NP03_T02_D02

Double underscore __

Separates the code block from the title, and every descriptive segment from the next — plus one at the very end.

…D02__Title__IsoA2__RevC__

Never use these in a new nameSpaces, hyphens -, the legacy _-_ pattern, or verbose suffixes like _-_Converted_From_PDF_Page_001. The parser tolerates some legacy forms, but they produce messy labels and unreliable sorting.

4The PDF + PNG pair

Each drawing is two files that share one base name and differ only by extension. The app builds both links by appending .png and .pdf to the base name in the manifest.

✓
NP03_T02_D02__NorthElevation__IsoA2__RevC__.png  +  …__RevC__.pdfSame base name, two extensions. PNG renders on the drawing canvas; PDF is the download link.
FileRoleBuild tool
.pngRaster shown on the drawing canvas (what users see and measure on).Preferred. Discovered first.
.pdfVector download / print copy behind the “Download PDF” button.Fallback if no PNG. Include it anyway.

Rule of thumb: export both every time. A PNG with no PDF loses the download; a PDF with no PNG loses the on-screen render.

5What the Build tool recognises

The Build tool (Update-ProjectManifest.ps1) scans each phase folder and writes the base names it finds into the project’s PlanVision__ProjectData__.json manifest, which the app then reads.

Picked up

  • .png and .pdf files
  • Base name stored (extension stripped)
  • Sorted alphabetically → your D## order

Ignored

  • Anything in a 00__Archive folder
  • .note and .html files
  • (HTML statement source is loaded separately)
Order = the D-numberBecause discovery sorts alphabetically, D01 … D09 … D10 appear in that order. Keep numbers zero-padded and sequential so the app lists sheets the way you intend.

6Where files live

Content sits under the project’s 20__PlanVision__AppContent folder, split by design phase. The phase folder’s number matches the T## in the filename.

20__PlanVision__AppContent/
├─ DesignPhase01__ConceptDesign__Content/      # T01 files
│   └─ 00__Archive/                            # superseded revs (ignored)
├─ DesignPhase02__PlanningApproval__Content/   # T02 files
│   ├─ NP03_T02_D01__ProjectIntroduction__IsoA2__RevB__.pdf/.png
│   ├─ NP03_T02_D02__NorthElevation__IsoA2__RevC__.pdf/.png
│   └─ 00__Archive/
├─ DesignPhase03__BuildingRegs__Content/       # T03 files (may use subfolders)
│   ├─ 01__Plans/  02__Elevations/  03__3dViews/ …
│   └─ 00__Archive/
└─ PlanVision__ProjectData__.json              # manifest (Build tool writes this)

The …__GoHere__.note placeholders just mark where files belong; they are never loaded. Put previous revisions in 00__Archive so only the current one shows.

7Special cases

Design & Access Statement

Use document code S## (e.g. S01). Any S## file is flagged as the statement and opens in the dedicated viewer. Title Design&AccessStatement renders as “Design & Access Statement”. It typically has an .html (viewer source, ignored by the Build tool) and a .pdf.

✓
NP03_T02_S01__Design&AccessStatement__RevB__.pdf

Sheet size

Optional but recommended on scaled drawings. IsoA2, ISOA2 or A2 are recognised, stripped from the title, and shown as “ISO A2” in the register. Without it the size column falls back to the folder default.

Revisions

Bump the letter (RevA → RevB) and move the superseded file into 00__Archive. Only the current revision should sit in the live phase folder.

10Exporter checklist

  • Project code is XX##, uppercase, not 00
  • Correct T## for the phase, and file is in the matching DesignPhase0N folder
  • Sequential, zero-padded D## (or S##) — this sets the running order
  • PascalCase title that describes the individual sheet
  • Sheet-size token (IsoA2) on scaled drawings
  • Revision (RevX) and a trailing __
  • Both .pdf and .png exported, identical base name
  • Single _ only in the code block; __ everywhere else; no spaces or -
  • Superseded revisions moved to 00__Archive

11Validation pattern (for the splitting skill)

A strict regex for a valid base name (extension removed). The runtime parser is more lenient — it classifies each __ segment rather than demanding a fixed order — but new files should match this exactly:

^[A-Z]{2}[0-9]{2}_T[0-9]{2}_[A-Z]{1,3}[0-9]{2,}   # NP03_T02_D02
(?:__[A-Za-z0-9&]+)+?                          # __Title (one or more parts)
(?:__(?:Iso)?A[0-9]{1,2})?                     # __IsoA2  (optional size)
__Rev-?[A-Za-z0-9]+__$                         # __RevC__ (+ trailing __)

Underlying rules from the app: project code ^[A-Z]{2}[0-9]{2}$; document code = the right-most letters+digits group in the code block; size detected by ^ISOA\d{1,2}$ or ^A\d{1,2}$; revision = any segment starting Rev; 00__Archive, .note and .html excluded from discovery.
